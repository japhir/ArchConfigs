* Research basis (2026-06, web search)
** Candidates considered
- *mutt_oauth2.py* — token fetcher shipped with the mutt project. Maintained.
  Supports devicecode and authcode flows. Stores token encrypted via a
  user-supplied decryption/encryption pipe (gpg / pass / keychain). Drop-in
  =PassCmd= replacement; rest of stack unchanged.
- *sasl-xoauth2 (tarickb)* — a SASL plugin that refreshes tokens *internally*;
  removes the need for any token script and also covers sending
  (msmtp/postfix). More moving parts; replaces the cyrus-sasl-xoauth2 plugin
  (conflict); reported O365 refresh quirks (issue #89), HVE needs
  refresh_window >= 600.
- *oauth2ms* — current. Dead upstream. Reject.

** Packaging reality on Arch (checked with pacman/paru)
- No XOAUTH2 SASL plugin in official repos at all (mainline =cyrus-sasl= ships
  gssapi/ldap/sql only). The XOAUTH2 *mechanism* is inherently AUR /
  build-from-source whichever route is taken.
- =mutt= and =neomutt= ARE in official =extra= repo. =extra/mutt= ships
  =/usr/share/doc/mutt/samples/mutt_oauth2.py= (+ =.README=). So Option A's
  token fetcher comes from an official-repo package.
- =sasl-xoauth2-git= is AUR-only (new dep); =cyrus-sasl-xoauth2-git= AUR-only
  (already installed).

** Decision: Option A (mutt_oauth2.py)
Rationale:
- Net-new AUR packages = 0. Reuses the already-installed, *maintained*
  cyrus-sasl-xoauth2 plugin (the only genuinely dead component is the fetcher,
  which this replaces).
- Token fetcher sourced from official =extra/mutt=.
- devicecode flow needs no local redirect HTTP server -> the =/etc/hosts= /
  port-bind class of failure cannot recur.
- Smallest, lowest-risk change: swap one =PassCmd=.
Pick Option B only if/when sending-side auth (msmtp/postfix) should be unified
under the same token manager.

Steps:

1. Ensure the script is available. Prefer the official package:
   - If `mutt` is not installed: `pacman -S mutt` (official extra repo), OR

2. Configure the registration in the script. Open `~/bin/mutt_oauth2.py` and
   set the Microsoft/registration block. Two sub-options:

      - client_id: <CLIENT_ID> (config.json "client_id")
      - client_secret: <CLIENT_SECRET> (config.json "client_secret")

   `--decryption-pipe` args wrapping `gpg --encrypt -r <key>` and
   `gpg --decrypt`. Confirm exact flag names from the README for the installed
   version before wiring.

4. First-time authorize (INTERACTIVE — the user must complete the browser /
   device-code login as i.j.kocken@uu.nl). Run the script with

5. Update ~/.mbsyncrc, IMAPAccount solismail only. Replace
     PassCmd /home/japhir/bin/oauth2ms

6. Test: `mbsync solismail` then `mbsync -a`. Both must exit 0 with no auth
